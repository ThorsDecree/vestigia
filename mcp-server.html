📡 CAPABILITY BROKER

VESTIGIA MCP Server

Tools with named boundaries.

The VESTIGIA MCP Server is a local-first capability broker between MCP hosts and explicitly exposed VESTIGIA systems. The model-facing tool description is not authority; executable policy and deployment grants decide what can happen.

Connected development version: 0.10.0.dev0. This is an unqualified development deployment, not a stable production release. Availability and exposed capabilities depend on operator configuration.

Three effect classes

  • Perceive: bounded reads and inspection.
  • Prepare: reversible drafts and staged proposals.
  • Act: consequential or canonical changes, protected by policy and explicit promotion.

Unknown native capabilities are denied by default. When linked to Runtime, Runtime's own capability registry remains authoritative for Runtime actions.

Current capability catalog

The live connected policy lists 69 named MCP capabilities, grouped below by subsystem. Each group can be opened independently. Availability still depends on the operator’s deployment settings, linked subsystem health, and the tool’s own permission checks; this catalog is a snapshot of the policy surface, not a promise that every operation is enabled everywhere.

Archive changes stay reviewable

Canonical text changes use a two-step boundary: stage a proposal, inspect its target and captured base hash, then promote the exact proposal if the deployment grant and unchanged-base check still pass.

Receipts and hashes help make the evidence trail inspectable. Reads, proposals, and completed effects remain distinct.

Where it connects

The server can expose configured Archive sources and selected capabilities to an MCP host. A Runtime can also use a separate, optional read-only MCP Archive window.

The current connected MCP deployment is not configured to inspect the active Discord Daemon-Bridge's logs or relay messages between its room and this chat.
